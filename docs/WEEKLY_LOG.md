**Week 9** — Implemented confidence propagation: path confidence is the product of edge confidences with older evidence decayed by 0.95 per day, measured from the entity's latest event (CERT timestamps are from 2010, so wall-clock decay would zero every edge). Added evidence paths from each user to the ATT&CK techniques they match, and a behavioural risk score that combines distinct techniques and discounts behaviour common among peers. Confidence is computed after the groundedness check from verified evidence only. Integrated all stages end to end (`scripts/run_pipeline_e2e.py`: 20 users, 7 stages, 0 errors). Fixed an edge-attribute bug that mislabelled edge sources and made retrieval about 50× faster (852 → 16 ms per query). Tabrez: confidence math, evidence layer, integration. Faizan: incident queue, confidence percentage and evidence trail on the dashboard. Bilal: edge-case and regression tests (confidence math hand-computed on three paths).

**Week 10** — Built the evaluation harness (`evaluation/metrics.py`, `evaluation/run_benchmark.py`) measuring retrieval accuracy, graph completeness, threat-correlation precision, response time and detection effectiveness, plus an ablation, a naive baseline, a threshold sweep and a groundedness fault-injection test. As the answer key was not yet downloaded, labels came from insider scenarios modelled on the three CERT r4.2 scenarios, injected into 12 of 60 real users. Results: detection F1 0.609 (precision 0.636, recall 0.583, false-positive rate 8.3%); removing the peer-prevalence discount raised the false-positive rate to 58%; graph completeness 100%; the groundedness check caught 15 of 15 fabricated citations with no false alarms. Tabrez: metric definitions and harness. Bilal: labelled scenarios, running benchmarks, tabulating results. Faizan: metrics panel on the dashboard.
